# Pixel Forensics

Use this skill when the wrong pixel, history, or overdraw is the question.

1. Name the expected color or event and the observed pixel region. If the user did not provide coordinates, first inspect an available capture export or event output with `read_image` and choose a provisional region from the reported visual feature. Label that choice as a candidate, record its image/source identity, and verify it against the native output texture and event before calling it observed. Missing user coordinates alone are not a stopping condition; if the image or mapping cannot be obtained, record the exact failed step and keep the region unknown.
2. Collect before / after / diff artifacts plus the region. A display screenshot may have different dimensions from the native texture: map the candidate only after checking the event, output resource, subresource and dimensions, then use native pixel/region/history reads to test it. A prose summary or an unverified screenshot coordinate is not enough.
   Before declaring visual references missing, inspect relevant images already declared by authorized materials, including retrieved Knowledge cards. Use `knowledge_read`'s returned `readImageArgs` with `read_image`; a Knowledge-relative declaration is not a workspace path, and a read failure must not become a claim that the source image does not exist. Initial attachments being empty does not make retrieved images unavailable. Historical images are appearance leads with their own provenance, never current-capture exports or current experiment measurements.
   Separate qualitative appearance assessment from quantitative reference matching. Different framing or exposure prevents a direct pixel-error comparison, but does not by itself prevent judging visible shadow structure, strands and plausible highlights alongside same-capture before/after/control evidence. Do not invent a requirement for a new same-exposure reference when the goal is qualitative; retain an explicit uncertainty or reject the candidate when the actual images do not support that goal. Mere darkening still does not pass. Inspect available authorized material before asking the user for replacement inputs.
   Make that judgment over explicit, bounded regions: the affected surface, representative shadow areas, useful highlights and an unaffected control. Actually inspect the disputed shadow regions in the available native-resolution images and state which structure or transitions remain, disappear or cannot be resolved. A darker shadow alone proves neither clipping nor preserved detail; visible highlights alone do not settle the shadow check. If the image cannot resolve the needed distinction, obtain a bounded regional readback while the variant is still active and preserve its coordinates, sampling and display conditions before rollback. Regional variation or nonzero values may corroborate an observation, but do not independently prove acceptable quality. Do not replace this finite check with an unrequested proof that every shadow pixel, the entire material model or production deployment is correct. Reject observed collapse or other regressions; use unknown only for a concrete unresolved observation after the applicable checks, not for a check that was simply omitted.
3. Walk pixel history or attachments only through configured RDC actions and `read_image`.
   For a candidate pixel, first inspect the history's actual event ids and valid pre-mod / shader-out / post-mod fields; a missing pre-mod value is unknown, not zero. Use a valid neighboring event and a nearby unaffected control from the same capture to compare event-before / event-after color and surviving fragments. Discover event ids from the action search or history rather than guessing adjacent integers. If the external reference has different framing or exposure, keep that comparison unresolved but continue these within-capture read-only checks before concluding that no discriminating test is possible.
   Check the active backend, output format and native field semantics before constructing a per-fragment blend ledger. Native Vulkan implementations can zero shader-out channels beyond the target's component count, retain an event-final post-mod value on the last fragment, and reconstruct per-fragment depth-test flags from quantized depth comparisons. An RGB target's reported alpha zero therefore does not by itself prove shader alpha zero; a failed fragment alongside a changed post-mod value does not by itself prove that fragment wrote the color. These are interpretation limits, not permission to rewrite returned values or assume every installed native build behaves identically. Establish applicability to the active build when possible; otherwise keep the disputed channels or fragment attribution unknown. Corroborate with event-bound texture reads, pipeline state and lifecycle-valid shader outputs or a discriminating reversible experiment. A partially populated native history is evidence, not a complete executable blend trace.
4. When this region is the earliest divergence, write it as the Debugger First Bad Event (`$debugger-causal-method`): `EvidenceRecord` with `region.kind` in `{event, pixel}` and an optional `observed_fact` companion Claim. Do not call that Claim causal.
5. Write Evidence first. Causal claims wait for a qualifying Experiment.

Do not blame the driver without distinguishing evidence. Do not treat a thumbnail caption as a measurement. Do not raise visual narrative to a new epistemic rank.
