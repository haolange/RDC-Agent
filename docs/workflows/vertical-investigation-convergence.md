# 垂直调查收敛计划

本文自足：按它执行不需要先读其他文档。它只回答三件事：要达成什么、按什么顺序做、每一步怎样算完成。

架构边界的权威是[垂直调查设计](../product/rdc-agent-investigation-design-analysis.md)。本计划的各阶段都在该边界之内；执行中若发现某一步必须越过它（新增存储、模型路由、Agent、固定流程或扩大权限），停下并报告，不自行决定。

## 1. 要达成的结果

用户给一句症状，Agent 能在当前 capture 上把问题查到证据允许的深度；换一个 capture 仍然成立。Debug 优先，Analysis 和 Optimize 随后。

衡量进度只看一个指标：**真实 Debug 轮次走到了主线的哪一步**。

| 步 | 含义 |
|---|---|
| 1 锚定 | 证明某个原生纹理区域、事件或 draw 就是用户所说的对象 |
| 2 首次异常 | 找到异常最早出现的事件，有读数为证 |
| 3 区分 | 至少一个竞争解释被观察削弱或排除 |
| 4 因果 | 有可恢复的对照实验支持结论 |
| 5 核验 | 独立审查看过当前版本的原始证据，没有未处理的质疑 |

现状：所有真实 Debug 轮次都停在第 1 步之前。测试数、门禁数、文档量都不是进度。

## 2. 执行规则

这些规则对每个阶段都生效，优先于"做得更周全"的直觉。

1. **一次只做一个阶段。** 做完交付并停下，等放行后再开始下一个。
2. **旁支只记不修。** 途中发现别的问题，在交付里记一行（现象、位置），不修、不查根因、不加测试。
3. **只改这一阶段点名的地方。** 不顺手重构，不加兼容分支，不加"以防万一"的判断。
4. **每个行为一条测试。** 只为本阶段新增或改变的行为写测试；不为假设中的情形补用例。
5. **方法文本只减不增。** 改 Skill 时净字节数不得增加；要加一句，先删掉等量的旧内容。
6. **不加规则、状态检查、门禁或报告**，除非本阶段明确要求。
7. **交付不超过一页。** 结论在前，每条结论配一个证据位置。答不出就写"无法判定"和原因，不铺陈可能性。
8. **验收记录每阶段只追加一条，不超过 15 行。**
9. **停止条件到了就停。** 不做"顺便"的事，不为了更稳妥再跑一轮。
10. 不绕过产品权限；不删除真实用户数据、凭据和原始 capture；结束时释放回放现场并停止自己启动的进程。

真实运行固定使用同一模型与推理档位、默认自动审核权限、不带 Memory。每轮记录：人工说过什么、耗时、token。

## 3. 阶段

分工：阶段 A、D、E 需要本机的 capture、设备和真实模型，由本机执行方做。阶段 B、C 不需要设备，由另一方在独立分支上做，与阶段 A 并行，互不等待。执行规则第 1 条对各方分别生效。

### 阶段 A：诊断（本机，不改任何代码和方法文本）

用**改动前**的方法文本跑，作为基线。

| 编号 | 问题 | 做法 |
|---|---|---|
| A1 | 已归档的最近一轮 PC 轨迹里，模型是否用过对象侧操作（Drawcall 高亮、事件前后输出差异、mesh）？每次结束前它自述的停止理由是什么？ | 只读归档请求，不运行模型 |
| A2 | 用户指出问题区域后，同一短症状能走到主线第几步？ | 一轮真实运行；用户以文字或一张圈出的截图给出区域，不给方法和原因 |
| A3 | 对 PC 最终输出纹理（TYPELESS 格式）取一次 Pixel History，颜色字段是数值还是 unknown？ | 操作员直接调用回放工具 |
| A4 | 对同一事件调用"事件资源使用"查询，Python 报错栈指向哪一行？"按资源查使用事件"是否成功？ | 操作员直接调用，记录回放进程加载的工具版本 |
| A5 | 操作员手工用 Drawcall 高亮或输出差异，能否在候选 draw 中认出眼部？ | 操作员直接调用 |

**完成标准**：五个问题各有一句结论和一个证据位置。
**停止条件**：五个问题答完。不修复任何发现。

### 阶段 B：方法文本（已完成，待合入）

调查方法已改写为一条正向主线（锚定 → 解释与预测 → 区分检查 → 决策点记录 → 独立核验 → 继续或交付），补上了对象侧定位，并要求规划阶段在对象或区域确有歧义时询问用户一次。

**阶段 A 结束后**再把这组改动合入本机分支，保证 A 是干净基线。

### 阶段 C：产品代码（不需要设备，单独排期）

按顺序逐项实现，每项单独提交。

| 编号 | 改什么 | 完成标准 |
|---|---|---|
| C1 | 规划阶段的事件树查询支持分页与搜索；只读探测的完整返回保存为可检索制品，不再截断后丢弃 | 规划请求能读完整棵事件树；规划身份仍不能做像素历史、调试或替换 |
| C2 | 模型声明 partial 后，运行时的复评反馈列出它自己写下的待做检查和未处理质疑的后续要求 | 请求中可见具体条目；仍只反馈一次，不增加续跑次数 |
| C3 | 派发独立审查时，自动把被审主张依赖的原始证据（图像、回执、测量）一并授予 | 审查首代不再因缺少来源而返回 partial；超出体量上限时列出未授予项 |
| C4 | partial 的未决项改为逐条结构：缺口、已尝试、阻塞类别、恢复条件 | 缺少阻塞类别的条目被拒绝；界面逐条展示；旧记录只读显示，不迁移 |
| C5 | 知识搜索结果直接显示每张卡的适用条件与排除条件 | 不读全文即可看到适用范围 |
| C6 | 上下文压缩的输入包含待做检查与未处理质疑的内容；补一条测试确认用户续跑后消费与期限不归零 | 压缩前后条目一致；续跑测试通过 |

**每项的停止条件**：完成标准满足，受影响测试、类型检查和 lint 通过。

### 阶段 D：回放工具修复（本机，仅在阶段 A 复现后做）

| 编号 | 前提 | 改什么 | 完成标准 |
|---|---|---|---|
| D1 | A3 复现 | TYPELESS 目标的像素历史按实际视图格式解释颜色；确实无法解释时返回原始通道值并标明"解释未知" | 同一调用返回数值 |
| D2 | A4 定位到枚举转换 | 未知枚举值返回原始数值并标明未知，不让整次查询失败 | 同一调用成功返回 |
| D3 | D2 完成 | 查询在回放调用返回之后才失败、且回放位置已证明恢复时，不隔离现场；把回放工具给出的失败类别传给模型 | 复现用例不再触发重开 |

A3 或 A4 未复现的，对应项不做，只记录。不推断 native 或驱动原因。

### 阶段 E：真实验证（本机）

B、C、D 合入后进行。每轮一个新会话、干净回放现场。

| 编号 | 材料 | 条件 | 通过标准 |
|---|---|---|---|
| E1 | PC 眼部 | 短症状；规划询问区域时用户选择跳过 | 到达主线第 1 步；记录最终到达第几步 |
| E2 | PC 眼部 | 短症状；用户回答区域 | 到达主线第 2 步或更远 |
| E3 | Android 黑发 | 短症状；隔离副本中**移除**该案例的历史知识卡 | 记录到达第几步 |
| E4 | Android 黑发 | 同 E3，但保留历史知识卡 | 与 E3 对比，说明知识改变了哪一步检查 |
| E5 | 用户提供的新 capture | 短症状；此前从未用于调整规则或方法 | 记录到达第几步 |
| E6 | PC | Analysis 一轮、Optimize 一轮 | Analysis 覆盖批准的每个目标；Optimize 基线带样本数与离散度 |

每轮结束后做一次**事后重放**：对 partial 里列为未执行的每项检查，操作员经同一产品路径亲自执行一次。成功说明 Agent 遗漏，失败说明工具或环境问题，并保留错误原文。

每轮归入且只归入一类：

| 类别 | 判据 |
|---|---|
| 自主完成 | 人工只做了计划批准和设备事实告知 |
| 事实补充后完成 | 另有用户指出区域或提供参考图 |
| 经方法提示完成 | 人工补充了调查方法或催促继续 |
| 合理 partial | 每个未决项的阻塞都被事后重放证实 |
| 过早停止 | 存在未执行检查，事后重放证明它可用 |
| 错误结论 | 与用户事后给出的真实原因不符 |
| 无效长跑 | 连续多轮工具调用后，锚点、解释集合、待做检查都没有变化 |

**停止条件**：六轮各跑一次并分类。某轮未通过时，只报告停在哪一步和事后重放结果，不自行开始修复。

## 4. 不做的事

- 不增加续跑次数，不用外部"继续"或停止钩子催促模型。
- 不新增存储、模型路由、循环引擎或 Agent。
- 不为 Debug 增加完成门禁。至今没有一轮到达完成，问题是做不到，不是乱宣称。
- 不在方法里写任何具体案例的对象、事件、资源或原因。
- 不用静默替代值掩盖失败；无法解释的数据在返回里明确标注。
- 不把工程检查通过当作真实调查通过。
