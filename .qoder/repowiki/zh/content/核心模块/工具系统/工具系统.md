## 更新摘要
**变更内容**
- **新增 read-before-write 强制执行机制**：在文件编辑和写入操作前必须成功读取目标文件，防止未经确认的修改
- **增强文件操作安全性**：通过 successfulFileReads 集合跟踪会话级别的读取记录，确保编辑操作的合法性
- **完善错误处理**：新增 READ_BEFORE_EDIT_REQUIRED 错误类型，明确指示需要先执行读取操作
- **跨轮次支持**：成功的读取记录在同一会话的不同轮次间保持有效，但不在会话重启后保留

## 简介
本文件系统性地梳理 RDC-Agent 的工具子系统，重点解释以下能力与机制：
- RdcCliInvokerService 的 CLI 调用机制：如何组装参数、调用外部 rdc CLI、解析协议并上报追踪。
- ShellInvocationService 的 shell 执行环境：进程生命周期管理、超时、孤儿进程隔离、结果归一化。
- CommandRegistry 的命令注册与管理：命令发现、别名、路由与执行。
- ToolPool 的工具池管理：工具实例缓存、元信息导出、清理策略。
- **新增** read-before-write 强制执行机制：确保编辑和写入操作前先有成功的读取操作记录，提升文件操作安全性。
- **已移除** agent_handoff 工具的执行能力：交接功能已完全转为 UI 驱动，不再作为可执行工具存在。
- **新增** 操作目录系统：基于 RdcOperationCatalog 的严格契约管理和能力驱动执行模型。
- **新增** 执行证据验证：通过 RdcValidatedEvidence 验证测量、干预和回滚操作的执行证明。
- 工具注册、权限控制、并发执行、结果缓存等关键特性。
- 工具接口规范、安全沙箱、错误处理与性能优化建议。
- 自定义工具开发指南与扩展现有功能的实践路径。

## 项目结构
围绕"工具系统"的关键代码分布在 main 层的 tools、agent-runtime、commands、runtime 等模块中：
- tools：封装对 rdc CLI 的调用（RdcCliInvokerService）、shell 执行（ShellInvocationService）、原生协议校验（RdcNativeProtocol）以及 RDC Shell 入口（executeRdcShell）。
- agent-runtime：定义 AgentTool 接口、工具池（ToolPool）、权限策略（AgentPermissionPolicy）、资源仲裁（ToolResourceArbiter）和工具调度（AgentLoop）。
- commands：提供通用命令注册与执行中心（CommandRegistry），用于 UI 或内部命令体系。
- runtime：进程与 shell 解析、环境变量注入、工作目录管理等基础设施。
- conversation：处理会话级别的交接逻辑（applyDeclaredHandoff），替代原有的 agent_handoff 工具。
- **新增** 文件访问控制：通过 fileReadAccess.ts 实现 read-before-write 机制，确保文件操作的安全性。
- **已移除** agent-handoff 相关的工具实现、状态存储和控制器。
- **新增** 操作目录：RdcOperationCatalog 提供操作定义验证、指纹计算和应用操作约束。
- **新增** 证据验证：RdcValidatedEvidence 验证执行结果的可信性和完整性。

## 核心组件
- RdcCliInvokerService：负责加载工具目录（catalog）、构建命令行参数、调用 ShellInvocationService 执行 rdc CLI，并将输出解析为统一的 ToolCallResult，同时发出追踪事件。
- ShellInvocationService：统一进程启动、超时、信号、孤儿进程检测、退出码归一化；维护活跃进程映射，支持按 runId 中止与全局终止。
- CommandRegistry：集中管理命令定义、别名、列表与执行；将用户输入解析为命令名与参数，路由到具体实现。
- ToolPool：以 name 为键缓存 AgentTool 实例，避免重复创建有状态工具；提供 all/allMeta 等查询能力。
- AgentTool：定义工具的统一接口（name、parameters、execute）与执行上下文（workspaceRoot、projectRootPath、sessionId 等），以及 spec 描述（只读/可并发/破坏性/副作用类型/类别/是否需要审批）。
- executeRdcShell：RDC 原生操作的强约束入口，校验会话租约、身份绑定、重放会话一致性，并在实验模式下生成签名收据。
- RdcNativeProtocol：严格校验 rdc CLI 返回的 JSON 信封（ok/result_kind/data/context_id），确保响应归属正确的 daemon context。
- **新增** ReadFileTool：实现安全的文件读取功能，支持行偏移和限制，成功后记录到 successfulFileReads 集合。
- **新增** WriteFileTool：实现文件写入功能，在执行前检查是否已成功读取目标文件，强制执行 read-before-write 机制。
- **新增** EditFileTool：实现基于搜索替换的文件编辑功能，要求先成功读取目标文件才能进行编辑。
- **新增** fileReadAccess：提供 recordSuccessfulFileRead 和 requireSuccessfulFileRead 函数，管理文件读取访问控制。
- **已移除** agent_handoff 工具：不再支持通过工具调用执行交接，交接功能已完全移至 UI 层。
- **新增** applyDeclaredHandoff：处理 UI 触发的会话交接，验证声明属于当前或刚批准的 profile，触发 before-handoff/after-handoff 钩子，写入 execution offer 并持久化 session.agentId。
- **新增** RdcOperationCatalog：提供操作定义的严格验证、指纹计算和应用操作约束，确保操作契约的一致性。
- **新增** RdcValidatedEvidence：验证执行结果的真实性，支持测量（event_durations/counters/image/frame_timing）、干预和回滚三种证据类型。
- **新增** RdcOperationPolicy：基于冻结的操作定义进行细粒度授权，验证作用域、影响、前置条件和路径访问。
- **新增** RdcTurnBindings：管理轮次级别的 RDC 绑定，包括 CLI 配置、操作定义和会话租约身份。
- AgentPermissionPolicy：基于模式（full-access/custom/auto-review/user）与规则集（白名单/黑名单/危险命令/读写根）判定是否允许、需审批或拒绝。
- ToolResourceArbiter：在同一 session/project 范围内串行化不安全工具效果，防止并发写冲突。
- AgentLoop：工具调度的编排器，支持分组并发、预算预留、失败聚合与流式更新。

## 详细组件分析

### RdcCliInvokerService：CLI 调用机制
- 配置与可用性：从设置读取 rdcCli 配置（enabled/command/workingDirectory/env/timeoutMs/catalogPath），并提供 isAvailable/getRuntimeSummary 暴露运行态。
- 目录加载：loadCatalog 支持从 catalogPath 加载工具清单，未配置时返回空目录；缓存已加载目录以避免重复 IO。
- 参数构建：normalizeCliArgs 将 --context-id 转换为 --daemon-context；buildCommandArgs 合并 settings.argsPrefix、全局参数、命令名与命令参数。
- 执行流程：executeCLI 通过 resolveRdcBatchInvocation 解析实际命令与参数，再委托 ShellInvocationService.invoke 执行；支持 timeout/cwd/env/runId/contextId/abortSignal。
- 结果解析：call 方法构造 call 子命令，附加 --args-json 与 --daemon-context，调用 executeCLI 后使用 parseRdcNativeResult 校验协议，再将 stdout JSON 转为 ToolCallResult；异常路径统一包装为错误结果并触发追踪。
- 追踪：onInvocationTrace 订阅 ToolTraceEntry，包含 turnId/toolName/args/result/timestamp/contextId/runtimeOwner/ownerLeaseId 等。

### ShellInvocationService：shell 执行环境

## 性能考量
- 目录缓存：RdcCliInvokerService.loadCatalog 缓存已加载的 catalog，避免重复 IO。
- 进程复用与隔离：ShellInvocationService 使用 processSupervisor 管理进程生命周期，支持超时与隔离，减少资源泄漏。
- 输出截断：ShellTool 对 stdout/stderr 进行环形缓冲与截断，防止大输出阻塞内存。
- 并发分组：AgentLoop 将安全工具分组并行执行，提升吞吐；对破坏性工具串行化，避免竞争。
- 资源仲裁：ToolResourceArbiter 在 session/project 范围内串行化写操作，降低冲突与重试成本。
- 超时与取消：所有长耗时操作均支持 timeoutMs 与 AbortSignal，及时释放资源。
- **新增** 读取记录缓存：successfulFileReads 集合提供 O(1) 复杂度的读取记录查找，避免重复文件访问。
- **新增** 路径规范化：使用 realpathSync 确保路径比较的准确性，避免符号链接导致的安全问题。
- **已移除** agent_handoff 工具的性能开销：不再需要维护复杂的交接状态机和 durable 存储。
- **新增** 操作定义缓存：RdcOperationCatalog 的深度冻结和指纹验证减少重复验证开销。
- **新增** 证据验证优化：RdcValidatedEvidence 的条件指纹计算避免重复哈希计算。
- **新增** UI 驱动交接的性能优势：避免了工具调用的序列化开销，直接通过 UI 事件触发。

## 故障排查指南
- CLI 不可用：检查 RdcCliInvokerService.getAvailabilityFailure 返回的原因（未启用/命令未配置/命令不存在）。
- 协议错误：RdcNativeProtocol.parseRdcNativeResult 抛出协议错误（exitCode!=0、非 JSON、缺少 result_kind/data、context_id 不匹配）。
- 进程问题：ShellInvocationService 返回 spawn_failed/timeout/unconfirmed_orphan；检查进程是否存在、超时是否合理、孤儿进程是否被清理。
- 权限拒绝：AgentPermissionPolicy 返回 deny/ask_user/auto_review/deny；查看命令是否命中危险模式、路径是否在工作区外、是否属于网络工具。
- 租约失效：executeRdcShell 在执行前后校验租约版本与 contextId；若变化，需重新 prepareTurn。
- 并发冲突：ToolResourceArbiter 串行化写操作；若出现竞态，确认是否正确使用 runExclusive。
- **新增** 读取记录缺失：write_file 和 edit_file 抛出 READ_BEFORE_EDIT_REQUIRED 错误；确保先执行 read_file 操作。
- **新增** 路径解析问题：successfulFileReads 使用真实路径作为键值，符号链接路径可能无法匹配。
- **已移除** agent_handoff 工具错误：不再出现 agent_handoff 工具未找到或执行失败的错误。
- **新增** 交接声明错误：applyDeclaredHandoff 可能返回 DECLARED_HANDOFF_NOT_FOUND、CONVERSATION_AGENT_UNAVAILABLE 等错误；检查声明是否正确配置。
- **新增** 操作目录错误：RdcOperationCatalog.validateDefinitions 抛出 RDC_TOOL_UPGRADE_REQUIRED 或 RDC_TOOL_CATALOG_FINGERPRINT 错误；检查 CLI 版本兼容性。
- **新增** 证据验证失败：RdcValidatedEvidence 抛出 RDC_TOOL_EVIDENCE_INVALID 错误；检查测量数据格式、干预状态或回滚身份。
- **新增** 授权失败：RdcOperationPolicy 抛出 RDC_TOOL_EXECUTION_DENIED 错误；检查操作作用域、影响类型或路径访问权限。

## 结论
该工具系统通过分层设计实现了安全的 CLI/shell 执行、严格的权限控制、可控的并发与资源仲裁、以及稳定的进程管理与协议校验。RdcCliInvokerService 与 ShellInvocationService 提供了可靠的底层执行能力；AgentTool 与 ToolPool 定义了清晰的工具接口与实例管理；AgentPermissionPolicy 与 ToolResourceArbiter 构建了安全与一致性保障；AgentLoop 则负责高效调度与错误聚合。

**重大更新**：新增了 read-before-write 强制执行机制，显著提升了文件操作的安全性。通过在 ToolExecutionContext 中维护 successfulFileReads 集合，系统能够跟踪每个会话中的文件读取记录，确保编辑和写入操作前先有成功的读取操作。这一机制有效防止了未经确认的文件修改，提高了系统的可靠性和安全性。

移除了 agent_handoff 工具的执行能力，将交接功能完全转为 UI 驱动。新的 applyDeclaredHandoff 机制通过用户界面交互触发会话交接，简化了交接流程并移除了复杂的状态机。新增的操作目录系统和能力驱动执行模型显著增强了系统的可靠性和安全性。RdcOperationCatalog 提供了严格的契约验证和指纹校验，确保操作定义的一致性和完整性。RdcValidatedEvidence 验证系统支持测量、干预和回滚三种执行证据类型，为实验性操作提供了可信的执行证明。RdcOperationPolicy 基于冻结的操作定义进行细粒度授权，防止未经授权的访问和修改。这些改进使得工具系统能够更好地支持复杂的自动化任务和诊断场景，同时保持高度的安全性和可靠性。

整体架构兼顾了可扩展性与安全性，适合构建复杂的自动化与诊断工具链。

## 附录：工具开发与最佳实践
- 定义工具：实现 AgentTool 接口，明确 name/description/parameters/spec/permissionHint；spec 应准确描述只读/可并发/破坏性/副作用类型/类别/是否需要审批。
- 上下文使用：通过 ToolExecutionContext 获取 workspaceRoot/projectRootPath/sessionId 等，确保路径与工作区一致，避免跨域访问。**新增** successfulFileReads 集合用于跟踪文件读取记录。
- 权限合规：遵循 AgentPermissionPolicy 的规则，避免危险命令与越权路径；必要时提供合理的 description 与参数说明以降低审批难度。
- 并发与资源：对于可并发工具声明 isConcurrencySafe=true；对写操作使用 ToolResourceArbiter.runExclusive 保护；对会话级操作使用 ShellTool 的会话锁。
- 超时与取消：所有长耗时操作支持 AbortSignal；合理设置 timeoutMs，避免长时间占用资源。
- 结果与追踪：返回标准化的 AgentToolResult；对 CLI 调用使用 RdcCliInvokerService 并订阅 onInvocationTrace 以便审计。
- 自定义扩展：通过 ToolPool.register 注册新工具；如需命令形式，可在 CommandRegistry.register 添加命令定义；如需 RDC 原生操作，封装 executeRdcShell 并遵守协议。
- **新增** 文件操作安全：实现文件编辑或写入功能时，必须调用 requireSuccessfulFileRead 验证读取记录；读取成功后调用 recordSuccessfulFileRead 记录读取操作。
- **新增** 读取记录管理：successfulFileReads 集合在同一会话内跨轮次有效，但不会在会话重启后保留；使用真实路径作为键值确保路径匹配的准确性。
- **已移除** agent_handoff 工具开发：不再需要实现 agent_handoff 工具，交接功能已通过 UI 驱动方式实现。
- **新增** UI 驱动交接开发：如需自定义交接流程，实现 applyDeclaredHandoff 的扩展点，正确配置 handoffs 声明和 requiredSkillIds。
- **新增** 操作目录开发：使用 RdcOperationCatalog 验证操作定义，确保符合契约规范；利用指纹机制保证操作定义的一致性。
- **新增** 证据验证：为实验性操作实现适当的证据验证，支持测量、干预或回滚类型；确保测量数据的真实性和完整性。
- **新增** 授权策略：遵循 RdcOperationPolicy 的作用域和影响类型限制；正确配置前置条件和路径访问权限。
- **新增** 轮次绑定：使用 RdcTurnBindings 管理轮次级别的绑定，确保 CLI 配置和操作定义的冻结一致性。
- **最佳实践** 交接设计：在 agent manifest 中正确声明 handoffs，确保 label、agent、prompt 与实际业务逻辑一致；使用 send:true 表示自动发送，showContinueOn 控制显示行为。
- **最佳实践** 文件操作：在进行文件编辑前，先执行读取操作获取文件内容；使用精确的搜索替换文本，避免误改；处理符号链接和硬链接时的安全风险。
