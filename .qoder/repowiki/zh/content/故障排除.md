## 简介
本指南面向 RDC-Agent 的安装、启动、配置、RDC-Tool 连接、Provider 认证、Agent 运行时问题及崩溃诊断。它把仓库中的失败分类、日志系统、CLI 调用器、错误分类器和 Shell 执行逻辑整合成可操作的排查流程，并给出常见错误代码含义、数据脱敏建议和报告问题时的最小证据集合。

## 核心组件
- **启动器与构建流程**：校验 Node.js 版本、解析 pnpm、恢复 Electron 二进制、进入桌面或浏览器模式。Node 缺失或版本不满足时会直接退出。
- **启动身份诊断**：主进程输出版本、载体类型、应用路径、用户数据目录等信息，用于快速识别部署环境。
- **运行时日志**：统一收集应用级与会话级日志，进行敏感信息脱敏、单条大小限制和渲染端广播。
- **Provider 错误分类**：将未知 Provider 错误标准化为 `aborted`、`provider_unknown`、`rate_limit`、`network`、`auth_expired`、`stream_protocol`、`unknown` 等，并决定是否可重试。
- **Shell 工具与 RDC-Tool 调用**：安全执行命令；RDC-Tool 操作需 General turn、冻结绑定、拥有 replay session、通过协议校验和可选实验回执验证。
- **能力探测服务**：对 LLM 模型发起最小请求，记录成功、配额耗尽、鉴权失败、路由不可用等结果，避免把临时配额问题永久标记为不可用。
- **崩溃上报**：可选集成 Sentry；未安装时仅记录警告，不影响应用运行。

## 详细组件分析

### 安装与启动问题
- Node.js 要求：启动器要求 Node.js 版本不低于约定版本；Windows 与 Unix 启动脚本会优先使用 `RDC_AGENT_NODE`，否则查找系统 `node` 或 Codex 内置 runtime。
- pnpm 与 Electron：启动器负责解析 pnpm、同步依赖、恢复 Electron 二进制；若 pnpm 命令失败、Electron 下载或解压失败，会直接报错。
- 启动模式：支持 `desktop`、`desktop-dev`、`browser`、`browser-dev`、`prepare-only`；非法模式会被拒绝。

常见症状与处理：
- 提示 Node.js 缺失或版本过低：安装符合要求的 Node.js，或通过 `RDC_AGENT_NODE` 指向有效 node 可执行文件。
- pnpm 安装失败：检查网络、pnpm 版本、锁文件和权限；查看启动器输出的 pnpm 命令和输出。
- Electron 无法恢复：确认 `node_modules/electron` 存在且平台匹配；必要时清理缓存后重新安装。
- 启动后立即退出：检查控制台中的 `[RDC-Agent]` 前缀输出，定位是 Node、pnpm、Electron 还是参数阶段失败。

### 配置问题
- RDC-Tool 配置：需要在设置中启用本地 RenderDoc 工具链，选择解压后的 `rdc-tool` 根目录，而不是 `.exe`。应用会自动检测自带 Python 与 CLI。
- 旧布局拒绝：如果检测到已废弃的 RDC-Tool 安装布局，会明确提示需要按新布局安装。
- 环境变量：可通过每行 `NAME=value` 的方式设置 RDC-Tool 环境变量；未显式设置中间目录时，桌面模式使用用户资源根下的 `rdc-tool-intermediate`。

常见症状与处理：
- “RDC-Tool CLI invoker is disabled”：在设置中启用工具链。
- “RDC-Tool CLI command is not configured”：填写有效的 RDC-Tool 命令或根目录。
- “command not found”：确认绝对路径或相对工作目录下的命令存在。
- “Python and CLI must resolve inside the same installation”：不要混用不同安装源的 Python 和 CLI。
- “retired installation layout”：卸载旧布局，重新解压官方 `rdc-tool` 包并选择根目录。

### RDC-Tool 连接问题
RDC-Tool 连接涉及三层：设置绑定、CLI 调用、Native 协议。

| 问题类别 | 典型错误 | 含义 | 建议步骤 |
|---|---|---|---|
| 未配置 | `RDC-Tool CLI invoker is disabled` / `RDC-Tool CLI command is not configured` | 设置未启用或未提供命令 | 打开设置 → 工具 → 启用本地 RenderDoc 工具链 → 选择 `rdc-tool` 根目录 → 验证 |
| 命令不存在 | `RDC-Tool CLI command not found` | 配置的路径无效 | 检查绝对路径、工作目录、符号链接和权限 |
| 绑定无效 | `RDC_BINDING_INVALID` | Python 与 CLI 不在同一安装内，或使用旧布局 | 重新解压官方 `rdc-tool`，选择根目录，不使用独立 Python |
| 版本不兼容 | `RDC_UPGRADE_REQUIRED` | CLI 提供的 schema 或 tool_version 不匹配 | 同时升级 RDC-Agent 与 RDC-Tool |
| 会话绑定失效 | `RDC_EXECUTION_DENIED` | 非 General turn、缺少冻结绑定、replay session 丢失、上下文变更 | 重新准备 turn，关闭并重新打开捕获，避免跨会话复用 |
| 协议不匹配 | `RDC_CLI_PROTOCOL` | RDC-Tool 返回结果不符合预期 | 升级 RDC-Tool，检查 stdout/stderr，确认未注入二进制输出 |
| 上下文隔离 | `RDC_CONTEXT_QUARANTINED` | replay 状态不确定 | 关闭捕获并重新打开，不要继续执行 |

### Provider 认证与连接问题
Provider 认证和网络问题由错误分类器和服务层共同处理。

| 错误代码或状态 | 含义 | 重试策略 | 用户可见建议 |
|---|---|---|---|
| `aborted` | 请求被取消 | 不可重试 | 检查用户停止、超时、AbortSignal |
| `provider_unknown` | Provider 未找到 | 不可重试 | 检查 Provider ID 与目录 |
| `rate_limit` | 速率限制 | 可重试 | 等待配额恢复，避免重复高频请求 |
| `network` | 网络错误、500/502/503/504 | 可重试 | 检查网络、代理、防火墙 |
| `auth_expired` | 401/403 且非 scope/unconfigured | 不可重试 | 重新登录或刷新凭据 |
| `auth_scope_denied` | 401/403 且与权限范围相关 | 不可重试 | 检查账号权限和 API scope |
| `auth_unconfigured` | 401/403 且提示未配置 | 不可重试 | 补全 Provider 配置 |
| `context_overflow` | 400 且上下文溢出 | 不可重试 | 缩短上下文、减少附件或历史 |
| `request_rejected` | 400 且请求被拒绝 | 不可重试 | 修正输入或模型约束 |
| `model_source` | 404 模型不存在 | 不可重试 | 更换可用模型 |
| `stream_protocol` | Provider 流协议违规 | 不可重试 | 升级 Provider SDK 或切换模型 |
| `PROVIDER_STREAM_EMPTY` | 流结束但无 assistant 正文 | 最多重试 1 次 | 重试后仍失败则记录诊断 |
| `quota-exhausted`（能力探测） | 配额耗尽 | 短期延迟重试 | 等待 60 秒后再次探测 |

### Agent 运行时常见问题
- **turn 循环停滞**：当 Agent 连续三轮产生相同工具结果时，系统应判定为 `CONVERSATION_AGENT_LOOP_STALLED`，不得误报为 Provider 失败。
- **turn 次数超限**：达到最大轮次仍要求 continuation 时，应报告 `CONVERSATION_AGENT_TURN_LIMIT_EXCEEDED`，不得静默完成。
- **工具执行失败**：Shell 工具只允许一次传入 `command` 或 `rdc`；RDC-Tool 操作必须由 General turn 持有冻结绑定执行，并在队列和执行期间保持上下文所有权不变。
- **Provider 连接中断**：空流、wire 失败、HTTP 5xx、429 应按失败分类处理；最终 Work Process 只显示一条诊断，避免重复错误噪音。

### GPU 调试问题
GPU 调试属于 RDC-Tool 与 RenderDoc 的领域问题。RDC-Agent 主要通过 Shell 工具和 RDC-Tool CLI 间接驱动原生工具，因此 GPU 调试失败通常表现为 RDC-Tool 协议错误或 native result 异常：
- 确认 RDC-Tool 能单独运行目标应用捕获。
- 检查 RDC-Tool 版本是否与 RDC-Agent 支持的契约匹配。
- 查看 RDC-Tool stderr 和 stdout，确认是否输出二进制或非 JSON 内容。
- 在 RDC-Agent 中优先使用受控 RDC 操作，而不是直接在 Shell 中执行任意 RenderDoc 命令。

### RenderDoc 兼容性问题
- 如果 RDC-Tool 返回非 canonical JSON、缺少 `result_kind` 或 `data`，会抛出 `RDC_CLI_PROTOCOL`。

## 性能注意事项
- 日志大小控制：应用日志上限约 1000 条，会话日志上限约 500 条；单条日志最大字节数有限制，字段会被截断，raw 可能只保留预览。
- Provider 流缓冲：Provider 流缓冲区有上限，协议违规不应重试。
- RDC-Tool 输出缓冲：CLI 调用默认输出缓冲上限为 8MiB，过大输出会被截断。
- 并发限制：Shell、write、task mutation、RDC/Live Capture、MCP、ask、output_register 等工具一律串行，避免并发造成 RDC 上下文冲突。
- 能力探测：配额耗尽类错误会触发短期延迟重试，避免频繁探测放大负载。

### 性能瓶颈识别
- 大日志：title、summary、detail、raw 组合超过 64KB 会被截断，大量 raw 可能拖慢序列化。
- 大输出：RDC-Tool 输出缓冲默认 8MiB，超大输出会导致截断。
- 频繁 Provider 重试：429、5xx 或空流会触发重试，过多重试会放大网络压力。
- 并发滥用：非并发安全的工具不应进入并发组，尤其 RDC/Live Capture。
- 长会话历史：上下文过大可能导致 `context_overflow`，应压缩历史或拆分任务。
