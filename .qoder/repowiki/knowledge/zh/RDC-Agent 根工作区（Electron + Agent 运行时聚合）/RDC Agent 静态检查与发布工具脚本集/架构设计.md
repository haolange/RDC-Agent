本模块以一组相互独立的 Node.js ESM/CJS 脚本构成，按职责划分为四层：
- 领域门禁层：`check-*.mjs`（如 `check-knowledge-system.mjs`、`check-investigation-system.mjs`、`check-renderer-structure.mjs`、`check-fidelity.mjs`、`check-provider-system.mjs` 等）各自声明规则注册表并调用共享引擎，通过 `process.exitCode = 1` 向 CI 报告失败。
- 系统债务引擎层：`system-debt-ratchet.mjs` 是核心库，定义统一的 `registry` 规则模型（`probe` 支持 `file-exists` / `dir-exists` / `contract-suite` / `walk-path-and-content` / `walk-pattern` / `profile-knowledge-ceiling`），实现“只允许新增、不允许扩大”的单调性约束；`knowledge-system-debt.json`、`investigation-system-debt.json`、`coverage-ratchet.json`、`design-tokens-baseline.json`、`renderer-contract.json`、`renderer-structure-baseline.json` 等 JSON 基线文件由 `--emit-measured` 生成并与历史基进行 diff。
- 保真度契约层：`extract-fidelity-contract.mjs` + `renderer-contract.mjs` 从源码提取 class name / data-testid 写入 `scripts/fidelity/.check-tmp`，由 `check-fidelity.mjs` 与 `fidelity-classnames.txt`、`fidelity-testids.txt` 对比；CSS z-index 顺序、组件结构等硬契约在脚本中以正则断言。
- 运行与发布层：`launch-rdc-agent.mjs`、`start-rdc-agent.{sh,cmd}`、`run-rdc-launcher.{sh,cmd}` 封装 Electron/RDC Agent 启动流程；`vitest-global-setup.ts` 通过 `setupFilesAfterEnv` 将 Vitest worker 的用户数据隔离到 `/tmp/rdc-agent-vitest-*`；`release/generate-checksums.mjs`、`release/generate-sbom.mjs` 生成 SHA256SUMS 与 SBOM；`provider-catalog-index.cjs`、`builtin-profile-contracts.mjs`、`pnpm-resolver.mjs`、`register-ts-source.cjs` 为运行时/包管理器注入提供支撑。
依赖方向单向：领域 check 脚本 → `system-debt-ratchet.mjs` → 文件系统/子进程；所有脚本均以仓库根为 cwd，不引入业务代码，仅通过路径扫描与正则匹配执行门禁。
