- 每个门禁脚本通过 `console.error` 输出带 `[tag]` 前缀的错误信息，并将 `process.exitCode` 置为 1 以向 CI 报告失败。
- 系统债务规则统一采用 `{ id, kind: 'missing'|'forbidden', probe, file, pattern?, unlessPattern? }` 对象声明，由 `system-debt-ratchet.mjs` 的 `evaluateRule` 分派执行。
- 基线文件（`scripts/fidelity/*.json`、`*.txt`）与对应 check 脚本成对存在，变更基线必须显式更新而非在运行时动态计算。
- 跨平台命令通过 `.sh` 与 `.cmd` 双后缀配对提供（如 `start-rdc-agent.sh` / `start-rdc-agent.cmd`），内部逻辑一致但调用方式适配 Windows/Unix。
- 测试隔离通过 Vitest `setupFilesAfterEnv` 的 `vitest-global-setup.ts` 集中设置 `RDC_AGENT_HOME`、`RDC_AGENT_USER_DATA`、`RDC_AGENT_QA_INSTANCE_ID`，确保每个 worker 拥有独立临时目录并在 teardown 中删除。
- 发布脚本位于 `scripts/release/` 下，统一以 `#!/usr/bin/env node` shebang 开头并使用 `path.resolve(path.dirname(fileURLToPath(import.meta.url)), '..')` 定位仓库根，避免相对路径依赖。
